# 知识库审阅与整理

管理页提供全局、项目、待确认、历史和已移出视图。有效记忆仍默认自动加入；不新增逐条人工审批环节。

## 参考的成熟产品

| 产品与一手资料 | 有用的组织方式 | 本项目采用 |
| --- | --- | --- |
| [Notion 数据库视图](https://www.notion.com/help/views-filters-and-sorts) | 同一内容的筛选、排序、分组与侧边预览 | 紧凑分组列表、类型与时间筛选、可收起的侧边审阅 |
| [Obsidian Bases](https://obsidian.md/help/bases)、[属性](https://obsidian.md/help/properties) | 用属性构建多种本地知识视图 | 将类型、适用范围、状态和时间作为清晰属性 |
| [思源笔记](https://github.com/siyuan-note/siyuan) | 本地知识与细粒度来源引用 | 从记忆直接查看用户原话、完整资料与修订记录 |

这里参考管理方式，不引入另一个笔记系统作为权威库。继续使用现有 FastAPI、SQLite 生命周期、MCP Memory Service 检索、FlashRank 重排与浏览器原生控件。

## 使用方式

- 左侧看全部记忆或全局记忆，也可以搜索项目。项目名称可以重命名，内部项目标识不变。
- 中间按类型或项目分组。显示筛选后的准确总数与当前载入数量，避免把分页数量误当总数。
- 未选记忆时列表占满剩余空间；点击条目才展开详情，再点一次或按 Esc 收起。详情栏可拖动调宽，双击分隔线恢复默认，支持键盘左右键调宽；可切换为展开阅读，手机上使用抽屉。只记住布局宽度，不保存记忆内容。
- 详情里看完整内容、适用范围、原话依据和修订历史。编辑、调整范围、移出或明确重新加入都从这里完成。
- 勾选后可批量设为全局、移动到项目或移出；待确认内容可明确加入。每次最多 100 条。
- 最近变更可以撤销；已有后续修改或已遗忘时，生命周期版本保护会拒绝覆盖。

## 全局与项目的区别

全局记忆是可跨项目复用的稳定偏好、身份环境和有条件的工作方法。例如 Word 修订规则只在文档任务相关时召回，不会在每次聊天时全部注入。

不能机械要求用户说“所有项目”才识别通用偏好。某个项目里提出的通用方法仍可能是全局；某张图的布局、特定软件配置、实验节点配额和一次性授权仍有原范围。混合要求按独立信息点提炼，保留条件，不通过删除条件来扩大范围。

本次复核以已有用户原话为依据，模型建议再作上下文检查；等义内容仍走现有协调与合并流程，不以扩大数量为目标。已确认的修订先在副本中执行，再用相同来源和目标版本事务提交，原始陈述时间不变。

## API 兼容与安全

GET /v1/memories 新增 kind、sort、limit、exact_project 参数，返回 items、total、offset、limit。原有默认 project 过滤仍包含全局，兼容已有客户端；管理页显式使用 exact_project=true，避免项目页面混入全局条目。智能体召回继续合并全局与当前项目范围。

POST /v1/memories/bulk 的 items 含 id 与 version，action 为 move、forget 或 activate。先验证整组所有权与版本，再于一个事务中整理；重复目标、版本冲突和其他用户的记录不会导致半批修改。已移出记忆不能通过移动或批量加入复活。activate 仅用于待确认记录。

PATCH /v1/projects/name 只更新当前用户已有项目的可读名称。项目名沿用已有用户隔离和 v2 导出恢复机制。

界面截图、真实原话、模型回执、数据库副本和逐项范围修订清单只保存在 D 盘私有目录，不进入 Git。自动化测试、真实模型范围测试、浏览器功能和正式库只读验收分别记录。
