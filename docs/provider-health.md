# 自动整理健康状态与权限变化

采集成功不等于提炼成功。Hook 将资料可靠保存到本机，后台原生交晓智请求完成提炼，再由记忆生命周期执行证据、范围、去重和版本校验。

## 模型与故障显示

- 当前源码默认模型为明确选择的 qwen3.7-max。旧安装配置不自动迁移；更换现有模型需要明确授权。本次本机迁移已获用户确认。
- 模型目录必须同时满足 Running、Granted、IsPublished。仅在目录中出现不足以证明可用。
- 路由授权缓存最多 60 秒；目录失败短暂缓存 30 秒，避免每个排队任务重复查目录。生成请求失败会立即使缓存失效，下一次执行前重新核验。
- 权限或目录预检失败发生在任务领取之前：资料保留 pending，attempts 不增加，稍后重查。已发起且结果不明确的请求保持 uncertain，不自动重放。
- 页面同时显示凭据配置、最近模型预检与完整的 owner 范围任务计数。模型阻塞显示“自动整理暂停”；failed/uncertain 不再被“已同步”掩盖；后台动态优先展示未完成记录，避免被后来的成功任务挤出列表。模型状态仅表示当前可观测证据，不能承诺未来调用必定成功。
- 预检状态仅在后台有实际任务时更新；页面读取不发起模型调用。上游故障摘要不包含请求原文、密钥、账号或会话标识。

## 显式授权后的补处理

先保存精确 SQLite 备份、原任务状态及源内容摘要到仓库外私有目录。保留已完成任务和已校验提炼检查点；对明确获准重试的未完成资料作有限新尝试，记录指定模型、完整响应和阶段回执。

跨项目的个人记忆先顺序核对，同一项目保持原时间顺序；不同项目可以并行。复用持久队列和原生限流守卫，按实际结果调整吞吐。入库继续走正式生命周期事务，保持用户/项目隔离、忘记抑制、等义合并和旧陈述不能覆盖新偏好。零条长期信息是合法结果。

验收区分自动测试、真实原生提炼、真实浏览器与实际入库统计。原始对话、失败尝试、响应及备份均不进入 Git。当前公开 local-v0.2.1 二进制安装包尚未重建；本改进在源码及已更新本机生效。

验证摘要见 [自动整理恢复验收](provider-health-acceptance.json)。
