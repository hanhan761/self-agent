# 自动整理、模型切换与网页提醒

用户已授权知识库在模型故障时自动选择备用模型。提供商始终为交晓智原生 API，账号和工作区保持现有授权；模型只能来自显式配置池，不扩展到任意目录型号。

当前本机优先 qwen3.7-max，备用 qwen-plus-latest。后者通过真实提炼及原文/范围校验；同次检查的其他候选未通过真实调用，没有纳入默认池。授权目录与故障状态会变化，这些记录不构成永久可用性保证。

## 切换和恢复

- 优先型号未获授权时，在发送提炼请求前选择当前已授权的备用型号。原生目录 Running/Granted/Published 是准入条件，不等于已完成真实回复验证。
- 创建会话、插入消息阶段的明确失败，以及明确的限流拒绝，可以在同一次操作中切换；每轮最多尝试配置池中的型号数。账号级 401/403 会暂停当前账号，绝不换账号规避授权。
- 已进入 Chat 且结果不明的断流/失败保留 uncertain。后续请求可以使用备用；这次请求需要明确重试，避免盲目重复消耗。
- 完整回复仍需结构、逐字原文、用户角色和记忆范围校验。一次格式修正后仍失败，隔离该模型；普通任务最多再用另一型号尝试一轮。已校验的提炼和逐条入库检查点保留，不重复已处理内容。
- 故障冷却从 60 秒开始逐次延长，至多 900 秒；供应商更长的 Retry-After 完整遵守。冷却后重新尝试优先型号，并区分“正在验证”与“已通过校验”。
- 型号冷却和最近十次切换写入仓库外 model-health.json，绑定账号、工作区、入口及配置池摘要。摘要不包含密钥、输入、回复或会话标识。迟到的旧成功不取消较新的冷却。

## 网页呈现

总览显示当前型号及自动切换状态；展开可查看池内型号的权限、冷却、实际校验时间和最近切换原因。切到备用后持续提醒；全部不可用显示整理暂停和等待数量；优先型号通过实际校验后显示恢复提示。

后台空闲时也会重新检查目录，正常间隔约 60 秒，失败短缓存约 30 秒。网页可见时每 5 秒刷新，返回标签页立即刷新。网页读取本身不触发付费生成，不弹出操作系统通知或控制台。

采集与检索独立运行；模型全部不可用时，新资料继续可靠保存在本机。failed/uncertain 在后台动态优先展示，不被新完成的任务挤出列表。

## 配置与冻结任务

配置字段为 xjtu_model、xjtu_auto_switch、xjtu_backup_models；池最多五个明确型号。新本地初始化默认启用已声明的原生模型池；普通 Config 默认关闭，旧配置和指定型号的冻结实验不会自行扩大模型范围。现有本机此次已按授权显式启用，其他客户端和登录设置保留。

冻结生成实验须禁用自动切换或仅保留协议指定模型，不能改变型号后沿用原成绩标签。知识库自然采集的自动策略不构成重新运行旧 uncertain 历史任务的授权。

不设置输出 token 上限，完整结束与结构/证据校验仍须满足。网络超时和响应字节保护不等同于输出 token 参数。

验证记录见 [模型切换验收](model-switch-acceptance.json)。原始资料、真实回复和精确私有状态保留在 D 盘，不进入 Git。现有公开 local-v0.2.1 安装包尚未重新打包；本改进在源码及已更新本机生效。
