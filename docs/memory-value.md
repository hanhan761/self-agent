# 记忆价值与可恢复整理

自动加入的条件除了用户原话依据，还包括具体用途：这条信息能否帮助未来助手作出不同且明确的选择？只出现“更高级”“照这个来”而没有对象、规则或上下文，不应成为长期记忆。

## 入库边界

- 保留具体偏好、可复用方法、稳定事实和仍有用的项目约束；不因文字短或只适用于单个项目而排除。
- 全局偏好跨项目使用；游戏窗口行为、某网站的技术架构等具体约束保留在原项目。
- 助手消息仅用于理解用户上下文。对带角色的会话，不将仅有助手引文的推断、建议或完成汇报变成用户记忆。
- 自动提炼使用原生 XJTU 模型进行价值判断，并继续执行完整输出、原话、范围和期限校验。极少数明显空泛或即时操作的表达另有确定性规则，在调用关系判断前拦截。
- 手动写入表达了用户的保留意图，不受自动价值拦截影响。

原生模型提示词和严格校验有不同作用：前者判断用途，后者验证结构、来源与边界；它们不能保证每次语义判断都正确。

## 整理旧记忆

本次旧库审核采用“模型建议 → 逐条复核 → 版本检查 → 事务归档”。模型建议不会直接删除记忆，也不代表所有建议都被采纳。通用偏好不能因为出现在某个项目会话里就被降为项目要求；尚未到期的任务和有用的参考位置也不能仅因一次性上下文而被清除。

低价值归档使用现有生命周期：

1. 校验所有者、当前版本、状态以及非手写来源。
2. 保存原始快照，将状态改为历史记录，记下归档原因。
3. 保留原话、原始时间和修订历史；自动召回排除已归档记录。
4. 管理页“历史记录”中打开详情，点击“撤销归档”，恢复此前的正式或待确认状态。若已有后续修改，拒绝覆盖并要求先查看历史。

它与用户明确“移出”不同；自动学习不会借撤销归档复活用户已移出的内容。SQLite 是权威状态，检索投影落后或恢复旧备份也不能使归档内容重新参与召回。原始对话留作追溯，并不等于全部进入长期记忆。

这不是定时清空旧记忆的任务，也不以固定天数、字数或跨项目复用次数决定删除。未来新增内容通过更严格的入库筛选；需要批量整理已有内容时，仍须证据复核和可恢复记录。

## 验证范围

新增回归覆盖空泛表达拦截、具体项目约束保留、手写保护、助手汇报排除、跨用户与版本保护、归档撤销，以及旧备份恢复后不复活归档内容。完整测试 230 项通过。

当前设备的 D 盘运行时已更新；真实浏览器验证历史详情、撤销入口、桌面与手机布局。原生模型三类实测分别验证了空泛要求不收录、具体方法保留、助手完成汇报不收录；最新真实需求的检索及项目隔离通过。原生模型补采与浏览器呈现分别验证，格式失败的响应不作为入库成功。此改进进入源码和当前设备，公开的 local-v0.2.1 安装包尚未重打包。
