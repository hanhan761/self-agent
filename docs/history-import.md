# 历史会话吸收与实测

历史导入需要用户授权，不因安装或更新而扫描所有个人文件。当前支持同一 Windows 用户的 Codex/Claude JSONL，会话原文件保持不变；原始内容、脱敏快照、模型回执、数据库与验收报告保存在仓库外的私有数据盘。

## 导入边界

- 流式读取冻结的文件前缀；大文件不再因超过 100 MiB 而整份跳过。超过 8 MiB 的单行按流跳过，后续用户消息仍可读取。
- 只接受所属用户目录内的会话，保留用户角色、项目、原始时间和稳定消息标识；自动执行、子智能体、工具运行输出、宿主注入和分析过程不作为用户事实。
- 选择题回答拆成智能体问题与实际用户答案。旧版没有 phase 的助手最终回复只作有限上下文，不作用户证据。
- 使用 [Yelp detect-secrets 1.5.0](https://github.com/Yelp/detect-secrets/tree/v1.5.0) 的离线检测器，禁止凭据在线验证。ad-hoc scan_line 会暴露低熵诊断候选，因此显式使用上游插件的熵阈值；短候选只移除所在行，不能全局替换单个字符。
- 沿用角色感知的分包器，不截断序列化 JSON。原话引文必须逐字支持提案；用户计划不改写成完成事实，探索问题不改写成决定。

## 归档与后台整理

历史批次先保存完整、已校验的提炼结果，再建立 history_pending/history_running 任务。普通实时工作器不抢占这些任务，显式执行必须匹配本机所有者。每条记忆与检查点在同一事务中提交，重复执行不会重复写入，已完成的提炼不会因索引等待再次请求模型。

个人默认按原始时间顺序合并，同项目串行、不同项目可并行。调用保持原生 XJTU 与显式账号/型号；专项批处理使用已安装交晓智工具的 durable_queue、共享 RateGovernor 和有限预算。不将项目管理器替换为第二套权威队列。

原生接口回执区分准备动作、Chat、HTTP 状态与上游错误代码。只有实际 HTTP 429，或完整匹配的已知 HTTP 500 包装限流签名，才能触发限流退避；普通 HTTP 500 或正文出现数字 429 不等于已确认限流。不记录凭据、请求头或任意错误正文。未知结果保持 uncertain，不盲目重放。

模型完成回复经过有限结构修复仍不能给出合法关系时，历史条目只进入 candidate 并保留来源，后续条目继续处理；不能使用非法关系覆盖旧知识。项目范围、类别、时间、版本、遗忘与期限仍由权威 SQLite 生命周期校验。

## 防止旧信息扩大影响

开始会话时按陈述发生时间选取默认约定，不按这次补录的时间排序。旧偏好不能覆盖更新偏好。某张图的布局只属于原项目，一次删除授权不成为未来删除许可。真实语料中发现的范围问题，通过有来源与版本保护的可撤销修订收窄；无法确定的记录不参与自动召回。

管理页提供项目可读名称，名称按用户隔离。v2 导出可携带可选 project_labels；恢复不会覆盖当前自定义名称，旧备份仍兼容。SQLite 包含权威内容、证据和生命周期；MCP Memory Service、SQLite-vec 和 FlashRank 仍只负责可重建的检索与重排。

## 验收方式

真实语料验收分别记录独立改写召回、原文回查、无关问题拒答、跨项目隔离与延迟，不能用原话搜索的命中率冒充泛化效果。对正式库做只读检查，恢复、遗忘不复活及其他用户隔离在 D 盘副本中验证。浏览器、MCP、原生模型和自动化测试分别记录。

图片、音频与附件未做 OCR 或内容提取；过滤与模型判断仍可能漏判，用户可以查看来源、修订或移出记忆。公开代码和技术说明不会包含实际聊天、个人信息、密钥、私有项目列表或运行回执。
